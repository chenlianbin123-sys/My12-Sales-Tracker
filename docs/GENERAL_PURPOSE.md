# 通用客户与事项跟进

当前 main 为 0.2.0-dev；v0.1.0 Release 仍是原有场景预览包，不会覆盖旧标签或替换其资产。

## 适用场景

可用于客户服务、商务合作、项目事项和小团队协作。不再要求使用主播/销售业务关系，也不限定四组。当前仍是单个组织的团队隔离模型，不是面向任意企业注册的多租户 SaaS。

| 角色 | 范围 |
| --- | --- |
| 管理员（0） | 全局看板、用户角色及团队设置、删除记录 |
| 负责人（1） | 本团队的录入、分配、查看、跟进及删除 |
| 成员（2） | 本团队中分配给自己的记录及跟进 |

团队使用正安全整数编号，0 表示未分配（管理员固定为0）。例如团队 1、7、105 都有效；管理员在用户管理页输入编号即可，无需先创建四个固定组。具有团队编号的负责人/成员才可访问相关业务数据。

## 单人使用

首次管理员仍需要由可信维护者在自己的测试环境建立，不能通过普通注册自选管理员。随后将自己的业务账号设为负责人、团队1，即可录入和跟进；没有普通成员时，新记录会分配给该负责人自己。无需创建虚构成员账号。

## 通用记录

- 客户/事项名称与联系电话至少填写一项，名称最多100字符，电话最多50字符。
- 电话可留空，适合项目事项；没有电话时列表不显示拨号和复制电话按钮。
- 名称加入列表、详情、关键词搜索和 CSV 导出，历史无名称记录继续显示电话。
- 当前通用流程：待处理 → 沟通中 → 方案确认 → 已完成/已关闭。流程内部代码仍为 NEW、CONTACTED、QUOTED、WON、LOST，不自动改写原数据。

## 升级兼容与部署

1. 先备份自己的数据库；在独立环境验证旧记录、团队105、负责人单人录入及成员跨团队拒绝。
2. 更新小程序和修改过的云函数：adminDashboard、adminUserUpdate、leadCreate、leadList（含 filters.js）、leadAssignSales、leadDelete、followUpList、followUpCreate、userStats；涉及文案的其他云函数也可随同发布。
3. 原字段 groupId、assignedSalesIds、createdByAnchorId、salesId 以及旧页面目录保留，是兼容协议名，不代表产品还限定原场景。
4. 旧数据中 WON/LOST 等代码现在显示通用名称，其原始含义没有被重写；若仍需原行业语义，应在部署前确认这些显示名称是否符合需求。
5. 看板按用户和记录实际出现的团队统计，每个集合最多读取10000条，超出时返回明确提示；它不是大数据量聚合方案，也不是并发快照统计。
6. 云端索引、数据库权限和真机流程仍需在自己的环境核对，仓库配置继续脱敏，未执行生产部署。

旧版安装及设计文档保留作历史参考；涉及四组和原业务角色的描述，以本说明及当前代码为准。
