# 线索工作台：10 项功能

主播与销售页面共用线索工作台。原有录入、跟进、删除及个人中心入口保留；删除仍仅向主播显示并由云函数鉴权。

| 功能 | 使用方式与边界 |
| --- | --- |
| 电话与备注搜索 | 输入最多 80 个字符并点击搜索；按字面子串匹配，不接受用户正则。搜索只在角色有权访问的范围内执行。 |
| 多种排序 | 最新录入、最早录入、最近跟进、跟进次数最多；ID 为次排序键。历史缺少排序字段的数据应在测试环境核对表现。 |
| 创建日期范围 | 起止日期独立可选，按中国时区自然日，结束日整天包含；起始日晚于结束日会提示错误。 |
| 未跟进筛选 | 包含 followUpCount 为 0 或尚无该字段的历史记录。 |
| 加载更多 | 每页 20 条，支持按钮与触底加载；显示已加载数和总数。改变筛选后从第一页重新加载。 |
| 精确详情查询 | 详情及新增跟进页按 leadId 查询，不再只在第一页寻找；仍附加当前角色和小组条件。 |
| 一键拨号 | 点击所选线索的拨号按钮，交由微信拨号界面处理。 |
| 复制电话 | 点击复制电话，将该条客户电话写入系统剪贴板。 |
| CSV 导出 | 导出已加载结果，含电话、状态、次数、销售、日期、备注；UTF-8 BOM，转义引号与换行，并处理常见公式注入前缀。 |
| 本机筛选偏好 | 用户主动开启后，按用户 ID 和页面角色分别保存状态、排序、日期和未跟进选项；不保存关键词或客户结果。关闭即删除本项偏好。 |

## 体验优化

- 支持一键清空筛选、失败重试和下拉刷新。
- 新请求会使旧请求结果失效，避免快速切换筛选时显示错乱。
- 刷新失败清空旧结果，避免旧结果被误当作新筛选结果导出。
- 新旧状态字段兼容：缺少 lastStatus 时按 status 筛选和显示。
- 每次进入列表重新获取用户信息；缓存角色仅作界面使用，实际访问权限由后端当前用户记录决定。

## 部署及验收

本轮修改 `leadList` 云函数（包含 filters.js），以及主播/销售列表、详情、跟进页和共用资源。无需新建数据库集合，没有自动修改历史数据。

1. 本地运行 `npm test`、`npm run check:public`。
2. 在自己的测试环境部署整个 `cloudfunctions/leadList` 目录，保留 SDK 依赖安装；更新小程序代码。
3. 云数据库可能要求新建索引，按控制台提示创建：组号/分配销售与所选排序字段、createdAt 范围、lastStatus/status 等组合。不同筛选组合需实测，不能保证一个索引覆盖全部查询。
4. 准备超过 20 条虚构线索，确认下一页、精确详情、状态筛选及跨组拒绝结果。
5. 验证关键词含 `.*[]` 等字符时仍为字面匹配；验证中国时区日期边界。
6. 用微信开发者工具及真机测试拨号、剪贴板和文件分享。旧版本不支持文件分享时显示提示。导出生成本机用户目录下 sales-leads.csv，再由用户在微信中选择分享；同名文件再次导出会覆盖。
7. 切换不同账号，确认偏好隔离；网络失败后确认能重试，未分组账号应被拒绝。

## 已知限制

- 未配置真实微信环境，尚未进行云端查询、编译或真机验收；仓库测试使用模拟 SDK，不替代真实环境测试。
- CSV 只包含已加载记录，导出前应看清数量；不提供后台全库导出。不要把 CSV 提交至公开仓库。
- 日期、未跟进与状态组合基于当前线索摘要字段。历史错误摘要需单独清理，不会在查询时自动修正。
- offset 分页遇到并发新增、删除、重新排序时可能移动；前端去重不能保证并发变更时完全无遗漏，需刷新重查。
- 子串搜索可能扫描较多数据，适合当前小规模项目；大数据量应改用专用搜索方案。
- 本轮没有解决跟进记录写入与线索摘要更新的事务一致性，也没有宣称完成全系统权限审计。

查询 API 参考：[腾讯云官方 Node SDK 数据库文档](https://github.com/TencentCloudBase/node-sdk/blob/master/docs/database/database.md)。本项目沿用 wx-server-sdk 的云开发数据库接口，具体组合索引需在自己的环境验证。
