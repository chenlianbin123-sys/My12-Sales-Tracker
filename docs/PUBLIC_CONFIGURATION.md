# 公开仓库配置与部署边界

本仓库保留 `YOUR_APPID` 和 `YOUR_CLOUD_ENV_ID`，不保存真实部署目标、登录凭据或私钥。`project.private.config.example.json` 是开发者工具本机配置的参考，复制到 `project.private.config.json` 后由 Git 忽略。

AppID、环境 ID 是标识符，本身通常不足以让别人登录；真正需要保护的是账号凭据、密钥、数据库访问规则和管理员授权。不要把隐藏标识符作为唯一权限措施。

## 发布前检查

```sh
npm run check:public
npm test
```

公开配置检查会确认两个示例占位符仍存在、私有配置未被跟踪，并扫描部分常见凭据模式。它只检查当前被跟踪的文件，不能证明不存在泄露，也不会自动清理 Git 历史。

## 本机部署

1. 本机复制示例私有配置，在微信开发者工具中配置实际 AppID。不要提交本机配置。
2. 部署时在本地设置真实云环境；如果修改 `miniprogram/app.js` 或公共项目配置，应在提交前恢复占位符。
3. 通过微信官方工具完成登录，选择正确云环境再上传云函数；根目录测试脚本不会执行部署。
4. 上传小程序代码前确认编译目标和体验成员，再通过官方流程预览、审核和发布。

目前未连接任何真实微信环境，也未部署云函数或上传体验版。已合并的源码更新与线上小程序发布是两个不同步骤。

## 如果历史上公开过凭据

先撤销或轮换凭据，再处理历史记录和平台缓存。删除当前文件无法撤销已泄露的凭据；历史清理会改变提交历史，应单独规划。
